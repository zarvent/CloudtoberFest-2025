Crea tu propia web con S3 en AWS

🎙️voice memo
📰 briefing doc simplified

Este documento resume la presentación "Cómo crear tu propia web con S3 en AWS", impartida por las estudiantes universitarias Dariana Pamayo y Nicole Ada León en un evento del AWS User Group de Santa Cruz. La charla ofreció una guía práctica y accesible para alojar sitios web estáticos con Amazon S3, un servicio de almacenamiento de objetos de Amazon Web Services.

Las presentadoras, líderes emergentes en la comunidad tecnológica local y promotoras del primer Cloud Club para estudiantes en Santa Cruz, estructuraron la sesión en tres partes: introducción a conceptos fundamentales, demostración práctica paso a paso y casos de uso. El contenido abarcó desde el flujo básico de una petición web hasta la configuración técnica de un bucket de S3, incluyendo políticas de permisos y habilitación del alojamiento web. La presentación destacó la simplicidad y potencia de S3 para proyectos como páginas de perfil profesional (landing pages) y blogs—contenido que no requiere interacción con bases de datos ni actualizaciones constantes. El evento también sirvió como plataforma para el aprendizaje y networking dentro de la comunidad local de AWS.

Introducción y Presentadoras

La charla fue dirigida por dos estudiantes de la Universidad Católica, futuras líderes en la comunidad tecnológica de Santa Cruz.

  • Dariana Pamayo: Estudiante de segundo año de Ingeniería de Software. Su interés por las tecnologías en la nube surgió a partir de un curso y un viaje académico. Es postulante a presidenta del primer Cloud Club de la universidad, una iniciativa para estudiantes que promueve el conocimiento de AWS a través de eventos y colaboración mutua, con aprobación formal esperada en noviembre.
  • Nicole Ada León: Estudiante de Ingeniería de Inteligencia Artificial. Se describió como el "apoyo moral" de Dariana, enfatizando que un líder siempre necesita una comunidad que lo respalde. Su objetivo en la charla fue fomentar un ambiente de aprendizaje mutuo, donde estudiantes y profesionales puedan compartir conocimientos, sin importar cuán básicos parezcan.

Análisis del Contenido

La sesión proporcionó los conocimientos teóricos y prácticos necesarios para desplegar un sitio web estático en AWS.

Fundamentos de las Páginas Web y AWS

Para establecer una base común, las presentadoras explicaron el flujo de una petición web mediante un diagrama con cinco componentes principales:

  1. Usuario: Realiza una búsqueda desde un dispositivo (computadora, celular, etc.).
  1. Navegador: Actúa como intermediario, tomando la petición del usuario.
  1. Internet: La "carretera" que transporta la petición a su destino.
  1. AWS (Amazon Web Services): El destino de la petición. Se describe como un servicio de Amazon que "alquila o renta espacios de memoria de sus máquinas que son supergigantes". En este caso, el servicio específico es S3.
  1. S3: Recibe la petición, la procesa y devuelve la respuesta, que viaja de regreso al usuario por el mismo camino (Internet y Navegador).

Conceptos Clave

Se definieron varios términos esenciales para comprender la solución propuesta.

ConceptoDescripción
Sitio Web EstáticoUn sitio web que no requiere actualizaciones constantes y no interactúa con bases de datos. Los usuarios solo pueden ver el contenido, similar a un blog. S3 está diseñado para este tipo de sitios.
Sitio Web DinámicoUn sitio que se conecta con bases de datos y necesita edición y mantenimiento constantes para interactuar con los datos de los usuarios.
Almacenamiento por Objetos (S3)A diferencia del almacenamiento por bloques o archivos, cada dato se guarda como un "objeto" con un nombre único. Se asemeja a una "caja donde puedes almacenar diferentes tipos de datos", desde archivosindex.htmlhasta bases de datos completas.
Bucket de S3El contenedor principal en S3 para almacenar archivos (objetos). Se utilizó la analogía de una "caja de mudanza" donde:<ul><li>Elbucketes la caja.</li><li>Losarchivosson los objetos dentro de la caja.</li><li>Elnombre del bucketes la etiqueta única de la caja, que debe estar en minúsculas y ser único globalmente.</li><li>Laregión de AWSes la ubicación física del servidor donde se almacena la caja (p. ej., Virginia o São Paulo).</li></ul>

Guía Práctica: Creación de un Sitio Web con S3

La presentación incluyó una demostración en video del proceso técnico para configurar un sitio web estático. Se mencionó que los nuevos usuarios de AWS disponen de una capa gratuita (5 GB) que es "más que suficiente para notionesta prueba".

Paso 1: Creación del Bucket

  1. Acceder a la Consola de AWS: Buscar el servicio S3.
  1. Iniciar la Creación: Hacer clic en "Create bucket".
  1. Configurar el Bucket:
    • Nombre del Bucket: Asignar un nombre único global en minúsculas.
    • Región de AWS: Seleccionar la ubicación del servidor. São Paulo (SP) es la más cercana y ofrece menor latencia.
    • Acceso Público: Desbloquear el acceso público para que el sitio sea visible en internet.
    • Configuraciones Adicionales: Dejar las opciones de versionamiento, etiquetas (tags) y encriptación con sus valores por defecto.
  1. Finalizar: Confirmar la creación del bucket.

Paso 2: Habilitación del Alojamiento de Sitio Web Estático

  1. Acceder al Bucket: Seleccionar el bucket recién creado.
  1. Ir a Propiedades: Navegar a la pestaña "Propiedades".
  1. Editar Alojamiento: Buscar la sección "Static website hosting" al final de la página y hacer clic en "Editar".
  1. Habilitar: Activar la opción de alojamiento de sitio web estático.
  1. Definir Documentos:
    • Documento de índice: Especificar el archivo principal de la web (p. ej., index.html).
    • Documento de error (opcional): Especificar una página para mostrar en caso de error (p. ej., error.html).

Paso 3: Configuración de Permisos (Política del Bucket)

  1. Ir a Permisos: Navegar a la pestaña "Permisos" del bucket.
  1. Editar Política: Hacer clic en "Edit" en la sección "Bucket policy".
  1. Aplicar Política JSON: Pegar una política en formato JSON para otorgar permisos de lectura pública. La regla principal permite a todos los usuarios ("Principal": "*") realizar la acción de obtener objetos ("Action": "s3:GetObject"), lo que significa que "todos pueden solo leerlo, no pueden tocarlo, no pueden cambiar nada".

Paso 4: Carga de Archivos

  1. Subir Contenido: Dentro del bucket, usar la opción para cargar los archivos del sitio web (index.html, CSS, imágenes, etc.).
  1. Buena Práctica: Se recomendó subir archivos y carpetas específicas en lugar de un repositorio completo en una sola carpeta, para evitar saturación e inconsistencias.

Paso 5: Acceso al Sitio Web

  1. Obtener la URL: Volver a la sección "Static website hosting" en la pestaña "Propiedades".
  1. Acceder al Enlace: El punto de enlace (endpoint) del sitio web estará visible. Esta URL, que contiene amazonaws.com, es la dirección pública del nuevo sitio.

Casos de Uso y Conclusión

Para ilustrar la relevancia de S3 en el mundo real, se mencionaron empresas reconocidas como Honda y compañías de videojuegos. Se citó una frase destacando sus beneficios: "[Tienen] esa presencia global y la habilidad de permitir que sus juegos sean accesibles para el público con [baja] latencia alrededor del mundo".

La conclusión: AWS S3 es una herramienta poderosa y accesible para desplegar sitios web estáticos de forma rápida y eficiente.
